01 · The challenge

What the challenge asked for.

The 8090 MIB Doc Challenge was a document-processing competition. Each input was a messy PDF packet containing forms, receipts, sponsor letters, biometric slips, registry pages, and manual notes. The output was one structured applicant record and one decision: approved, denied, or needs review.

The submitted system had to run inside Docker with no network, using CPU only, and average less than six seconds per PDF. The dataset included scans, damaged pages, conflicting evidence, and hidden text intended to mislead a naive extractor.

How it worked

The processing steps.

The pipeline used visible PDF text first, rejected hidden content, applied OCR where needed, kept the source of each value, and then applied deterministic decision rules.

  1. 01ReadVisible text and rendered pixels
  2. 02FilterRemove hidden and off-page instructions
  3. 03RecoverUse OCR where evidence is weak
  4. 04TraceKeep page, geometry, source, and trust
  5. 05DecideApprove, deny, or send to review
